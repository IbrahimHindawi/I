I compiler

I is a focused C front-end: direct declarations, monomorphized generics, automatic reflection, typed formatting, and generated C that the native toolchain compiles normally.

Quickstart

Compiler repo and package flow

Build compiler

Builds I.exe, ibind.exe, and the packaged standard library.

python bunyan.py build debug

Package output

The build copies the compiler and src\std into a folder that can live on PATH.

C:\devel\i-windows-x64\
    I.exe
    ibind.exe
    std\

Compile an I file

The compiler finds the sibling std folder automatically.

I.exe compile src\main.i -o build\i_gen\main.c --header build\i_gen\main.h

Check only

Used by editor tooling and diagnostics without producing build artifacts.

I.exe check src\main.i --diagnostics=json

Shape

Small syntax, explicit output

The language stays close to C. The compiler owns the type system, generics, reflection, diagnostics, and C emission.

Declaration-first syntax

name: type is used for locals, globals, fields, structs, enums, aliases, and procedures.

Native monomorphization

Array<payload> and sum<payload> emit concrete C structs and procs.

Typed operations

Generic algorithms can call typed implementations such as add<T> and resolve per concrete type.

Automatic reflection

Payload<> lowers to immutable metadata for field names, offsets, sizes, enum values, and type facts.

Compiler-driven formatting

printfmt("{}" resolves argument types and lowers to concrete print<T> calls.

C interop remains direct

cinclude, external, and external_emit keep C APIs visible without wrapping everything.

Line mapped generated C

Generated C uses #line so native compiler errors and debugger stepping can point back to I source.

Editor path

The LSP shell can call I.exe check --diagnostics=json and publish compiler-owned diagnostics.

Syntax

Current language examples

Basics

Unified forms

  • value: T = expr;
  • Name: struct = { field: T; }
  • name: proc(args)->T = { ... }
  • Generic: struct<T> = { ... }

Metaprogramming

  • Payload<>.field_count
  • Array<T> native generic types
  • print: proc<Payload>(...) typed operation specialization
  • printfmt("{}\n", value) compiler lowered formatting

Interop

  • cinclude "stdio.h"
  • define("FLAG")
  • proc[WINCALL](...)
  • external and external_emit

Compiler

One merged generated unit

I imports are resolved by the compiler, then emitted as C in a deterministic order.

Default project compile

I.exe compile src\main.i -o build\i_gen\main.c

If no header path is given, the compiler can derive the companion header path from the C output path.

Generated files

build\i_gen\
    main.c
    main.h
    Array_payload.h
    Array_payload.c

Generated native monomorph headers stay build-local. Authored code remains .i.

Diagnostics

I.exe check src\main.i --diagnostics=json --stdin-path src\main.i

The compiler is the source of truth for errors; the LSP should stay a thin transport layer.

Standard Library

Small runtime, arena-shaped

Containers

Array.i, Vec.i, Node.i, List.i, Map.i, Option.i, and Result.i are I-native runtime modules.

Strings and paths

string8 owns arena memory, string8slice borrows, and path helpers normalize slash handling at the I level.

Printing

Print.i provides concrete printers; printfmt uses compiler type information to pick the right printer.

Debug

Use the native toolchain

  1. 1

    I source is translated to C with #line directives.

  2. 2

    clang-cl compiles the C into normal debug info.

  3. 3

    Visual Studio can step the I source while native disassembly stays available.

  4. 4

    If the generated C matters, it is still visible under build\i_gen.
